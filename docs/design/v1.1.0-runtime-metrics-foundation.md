# 运行基础指标：第一阶段

- 原因：总览将累计文件数显示为速度，剩余时间始终为计算中；上下行共用可变化的分母，未知工作量被显示为 0%。
- 范围：统一总览、任务列表、任务详情、活动管理、任务设置和任务状态 API 的实时阶段、阶段处理数量、已用时间与等待原因；桌面顶栏、侧栏和托盘共用执行状态。
- 不包含：字节采集、速度、ETA、每日统计重构和历史数据补算。

## 数据契约

- 状态 API 新增可空 `runtime`，旧计数与历史记录保持兼容。
- 每次实际执行有内存 `execution_id`；无变化检查不强制创建持久化运行记录。
- `phase`、`direction`、`pass_kind`、`segment_id` 明确本次阶段范围；上下行和补齐阶段分别计数。
- `processed/total` 统计本阶段已完成处理的对象，包含失败或跳过；不代表同步成功。重试不重复增加处理数，取消中的对象不计入。
- 扫描时 `total=null`，只显示 `discovered`；已知空集合为 `total=0`。
- `processed_total` 为本次跨阶段处理次数；同一对象分方向或补齐重复处理会分别计数，不称为独立文件数。
- `current_item` 在对象真正开始处理时设置，处理结束后清除；不从上一条日志推导。
- 已用时间由后端单调时钟采集，包含扫描、限流、重试及远端等待；结束后冻结。
- 等待原因包括客户端限流、远端限流、自动重试、远端导入或导出；只有已知重试安排才提供倒计时。
- `wait.resume_at` 是下一次已安排动作的时间，可能是下一次远端状态查询；不代表导出、导入或整个同步的完成时间。界面只对限流和重试显示重试倒计时。
- `sampled_at` 是快照时间；`activity_at/progress_at` 由执行器更新，接口轮询不伪造执行进展。

## 交互与边界

- 页面共用同一解释函数；未知阶段数量不回退为整体百分比。
- 状态轮询保持 5 秒；前端插值显示已用时间，不额外请求飞书。
- 连续 15 秒未收到快照时显示“状态暂未更新”，冻结为上次记录的已用时间，并停止重试倒计时。
- 无进展不自动认定卡死；正常等待显示真实原因。
- 运行快照只存内存；阶段与等待采集不逐项新增数据库活动记录。
- 每次执行绑定独立上下文；结束后的旧回调不再修改指标；不同账号和任务不共享等待状态。
- 周期上传预检期间，页面展示临时执行快照；没有变化时恢复上次正式运行的快照，不新增历史记录。预检不展示上次运行的 ID 和结果计数。
- 活动管理独立显示当前执行；历史列表和事件区保留所选运行的结果。预检保留的旧运行 ID 不关联新的阶段与耗时，正式运行和收尾阶段才关联实时执行。
- 历史运行耗时只按开始/结束时间计算；没有结束时间时显示进行中或暂无，不以最后一条事件的时间代替结束时间。
- 桌面状态按账号隔离缓存；顶栏与托盘的运行数包含扫描预检和收尾。桌面连续 15 秒无响应时显示未知运行数，账号侧栏显示状态待更新。
- 全局立即同步跳过正在执行的任务，避免扫描阶段再次触发同一任务。
- 本地扫描在线程中进行，使后端在遍历目录时仍能返回状态；扫描被新执行接替时，旧检查不会替换新执行的指标。

## 口径样例

- 云端扫描发现 235 项：显示“扫描云端 · 已发现 235 项”，不渲染百分比进度条。扫描发现量包含目录和文件。
- 下行处理 100 项后切换上行 3 项：上行起始为“本阶段已处理 0/3 项”，不会沿用下行累计计数。
- 上行 3 项中 1 项成功、1 项失败、1 项跳过：阶段处理量为 3/3，成功与失败仍分别由结果计数表达。
- 同一项重试 2 次后成功：处理数量只增加 1；等待期间显示真实重试原因。
- 快照记录已用 65 秒，15 秒内没有新快照：到达 15 秒阈值后显示“状态暂未更新”和“已用 1 分 5 秒（上次记录）”。
- 后端系统时钟回拨，单调时钟仍推进 65 秒：已用时间为 65 秒；结束后不继续累计。

## 验证范围

- 未知扫描、阶段切换、补齐、失败和跳过的计数、取消、终态计时、时钟校正。
- 限流与远端等待嵌套、并发任务隔离、无变化检查的历史兼容。
- API 兼容、全应用一致展示、状态过期与未知值处理；历史结果不混入当前执行。
- 开发联调和打包安装启动体验。
