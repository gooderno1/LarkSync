# v0.8.10 活动布局、字体与问题处理设计

## 1. 目标与范围

本版本解决三个已在正式版验证的问题：

- 活动管理标准窗口的信息层级不合理：任务列表长期占据左栏，运行却只能用下拉框切换。
- 全局正文、说明和表格文字仍偏小；只放大字体会造成控件、行高和固定列宽不匹配。
- 问题中心虽然已有“已忽略”页签和 `ignored` 状态，但没有忽略、恢复和审计入口。

本版本不改变桌面壳的侧栏、顶栏和窗口断点，也不修改同步算法、问题分类器或正式数据。数据库升级只新增兼容字段，不批量改写现有问题状态。

## 2. 正式数据只读核对结论

核对时间：2026-07-28。核对方式：以 SQLite `mode=ro` 打开正式库，只读取聚合字段和问题元数据。

- 当前未解决问题共 9 条。
- 6 条为 `system / diagnostic_only`，首次出现时间介于 2026-05-20 至 2026-06-29；其中 3 条在 2026-07-28 又被诊断源碰到，因此“最近发生”被刷新。
- 2 条为 `upload / auto_recovering`，均首次且最近出现于 2026-07-08。
- 1 条为 `local_io / auto_recovering`，首次且最近出现于 2026-06-08。
- 9 条均有关联任务；当前没有严格匹配的“同任务 + 同对象 + 同操作族 + 更晚成功”恢复事实。
- 因为当前系统既不能凭弱证据自动结案，也没有人工忽略入口，所以这些历史项只能持续挂在未解决列表。

结论：不能用时间阈值批量删除或自动标记解决。需要补齐人工“暂不处理”生命周期，同时继续保留可信恢复事实自动结案。

## 3. 活动管理响应式布局

### 3.1 紧凑模式

适用条件沿用现有窗口断点：宽度小于 1280px 或高度小于 760px，并保留滞回。

- 顶部保留任务、运行两个下拉框。
- 下方只显示事件主列表。
- 点击事件进入整页详情，返回后恢复任务、运行、筛选、分页和滚动上下文。
- 不新增常驻任务栏或运行栏，避免在窄窗口压缩事件内容。

### 3.2 标准模式

适用条件沿用现有窗口断点：非紧凑且未进入宽屏。

布局从“任务列表 + 运行下拉/事件”改为：

1. 标题和统计区下方增加单行任务选择区。
2. 任务使用全宽下拉框；同一行显示当前任务状态、真实活动运行数量和“仅显示有实际动作的运行”说明。
3. 主工作区使用左右两栏：
   - 左栏固定 296px，显示可滚动的运行记录。
   - 右栏使用剩余宽度，显示事件筛选、事件列表、分页和事件详情抽屉。
4. 运行记录使用完整卡片，不再使用标准模式运行下拉框；卡片展示运行标识、时间、状态、上传/下载/删除/异常统计和耗时。
5. 任务切换时沿用现有选择策略：优先选择该任务最近的真实活动运行；若无真实活动，运行栏显示明确空状态，事件区不伪造 0 条成功记录。

标准窗口在 1280px 物理宽度下的正文宽度约为 988px：296px 运行栏 + 16px 间距 + 至少 676px 事件区；默认 1360px 窗口下事件区约为 756px。事件表格列宽同步收紧为可在事件区内完整容纳的布局。

### 3.3 宽屏模式

适用条件沿用现有窗口断点：宽度至少 1500px 且高度至少 820px，并保留滞回。

- 保持任务、运行、事件三栏。
- 任务栏从 248px 调整为 252px，运行栏从 288px 调整为 292px；放大的文字主要通过卡片高度和换行适配，避免超过宽屏断点下约 1208px 的真实正文宽度。
- 事件区最小宽度从 640px 调整为 632px；三栏与两段 16px 间距合计 1208px，和 `1500px - 228px 侧栏 - 64px 正文边距` 的壳层宽度一致。
- 任务搜索框、任务卡片和运行卡片随新字阶增加高度，不改变选择逻辑。

### 3.4 选择与模式切换

- `selectedTaskId`、`activeRunId`、事件筛选、关键字、时间范围和分页继续由现有 hook 管理。
- 标准与宽屏互切时只改变呈现方式，不重置任务或运行。
- 进入紧凑模式时将现有任务、运行映射到两个下拉框；返回标准或宽屏后恢复卡片选中态。
- 事件详情打开时，标准/宽屏继续使用右侧覆盖抽屉，不挤压底层表格。

## 4. 全局字阶与密度

### 4.1 字阶

全局字阶整体上调 1px，并同步提高行高：

| 用途 | 旧值 | 新值 |
| --- | --- | --- |
| 微型辅助信息 | 11/16px | 12/18px |
| 元信息 | 12/18px | 13/20px |
| 说明/表头（`text-xs`） | 13/20px | 14/21px |
| 正文/控件（`text-sm`、body） | 14/20px | 15/22px |

页面标题 `text-xl`、详情标题 `text-lg` 保持 Tailwind 原值，避免标题层级膨胀。

### 4.2 排版配适

- 常用下拉框、输入框和按钮从 36px 高调整到 40px；主选择器使用 42px。
- 活动事件表格行从最小 44px 调整到 48px。
- 问题队列卡片、页签、底部动作区增加垂直留白。
- 活动标准/宽屏栏宽随字体增加；问题中心队列从 288px 增至 304px，宽屏动作栏从 320px 增至 328px。
- 不使用全局缩放；字体实际像素增加，避免位图化或缩放模糊。
- 长路径继续截断并保留 `title`，证据区继续换行并可滚动。

## 5. 问题“忽略”生命周期

### 5.1 语义

“忽略”表示用户确认当前问题暂不处理：

- 问题不再计入未解决数量。
- 问题、出现记录、证据和处理记录全部保留。
- 忽略不等于解决，不伪造成功事实。
- 已忽略问题可恢复到未解决。
- 不提供批量忽略，防止一次误操作隐藏大量真实故障。

### 5.2 状态转换

| 当前状态 | 触发 | 下一状态 | 说明 |
| --- | --- | --- | --- |
| `open/in_progress/waiting` | 用户确认忽略并填写原因 | `ignored` | 取消当前等待语义，记录原因、时间和动作审计 |
| `ignored` | 用户恢复处理 | `open` | 清除当前忽略原因/时间，历史动作仍保留 |
| `ignored` | 同指纹失败再次出现 | `ignored` | 增加次数并更新最近发生时间，不反复打回未解决 |
| `ignored` | 出现严格匹配的后续成功事实 | `resolved` | 客观恢复优先，自动结案并记录验证依据 |
| `resolved` | 更晚的同指纹失败再次出现 | `open` | 沿用现有重新打开规则 |

### 5.3 忽略原因

忽略弹窗提供预设原因和补充说明：

- 已确认不再同步此对象
- 历史问题，当前无需处理
- 外部条件限制，暂时接受
- 其他

提交到后端的是一条完整原因文本，去除首尾空白，长度限制为 2–200 个字符。不能提交空原因。

### 5.4 数据模型与审计

`problems` 新增：

- `ignored_at REAL NULL`：当前忽略发生时间。

沿用：

- `ignored_reason TEXT NULL`：当前忽略原因。
- `problem_actions`：新增动作键 `ignore_problem`、`restore_problem`，记录请求时间、完成时间、结果和验证说明。

schema v6 只补列和索引，不批量修改原状态。旧版数据库升级后，原有问题原样保留，所有用户都使用同一迁移逻辑。

### 5.5 API

- `POST /problems/{problem_id}/ignore`
  - 请求：`{"reason": "历史问题，当前无需处理"}`
  - 允许状态：`open/in_progress/waiting`
  - 重复忽略返回 409。
- `POST /problems/{problem_id}/restore`
  - 无请求体。
  - 只允许 `ignored`。
  - 重复恢复返回 409。

两个接口都返回更新后的完整问题对象。动作审计与问题状态在同一数据库事务内提交。

### 5.6 页面交互

- 未解决页：每个选中问题都显示“忽略问题”按钮；已有真实修复动作时，忽略作为次级动作。
- 已忽略页：显示忽略原因、忽略时间和“恢复处理”按钮。
- 已解决页：不显示忽略或恢复按钮。
- 点击“忽略问题”打开原因弹窗；确认前不改变状态。
- 点击“恢复处理”使用轻量确认框；确认后切回未解决语义，当前已忽略列表自动刷新。
- 紧凑模式的动作放在详情底部；标准模式放在工作台底部；宽屏模式放在独立动作栏。
- 操作成功后刷新问题列表、摘要、详情和动作历史；若当前项离开当前页签，自动选择当前页下一条。

## 6. 错误与并发

- 问题在弹窗打开后若被自动解决，提交忽略返回 409，页面刷新并提示状态已变化。
- 问题在其他窗口已恢复时，重复恢复返回 409。
- API 失败不做乐观更新，页面保留当前数据并显示错误提示。
- 新发生事件与人工忽略并发时，以事务提交顺序为准；同指纹新失败不会主动解除已提交的忽略。
- 自动恢复事实可以覆盖 `ignored` 为 `resolved`，因为它代表客观状态已经恢复。

## 7. 测试与验收

### 7.1 后端

- schema v5 升级到 v6 后存在 `ignored_at`，历史状态不变。
- 忽略时状态、原因、时间和动作记录原子写入。
- 非未解决状态不能忽略；非忽略状态不能恢复。
- 恢复后回到 `open` 并清除当前忽略字段。
- 同指纹新失败保持 `ignored`。
- 严格匹配的恢复事件将 `ignored` 转为 `resolved`。
- API 校验空原因、超长原因和并发状态冲突。

### 7.2 前端

- 标准模式包含顶部任务选择器，主区为运行/事件两栏，不再出现标准模式运行下拉框或常驻任务栏。
- 紧凑模式仍有任务、运行两个下拉框。
- 宽屏模式仍有任务、运行、事件三栏。
- 未解决问题显示“忽略问题”；已忽略问题显示原因和“恢复处理”。
- 忽略弹窗要求原因；相关 mutation 会刷新列表、摘要和详情。
- TypeScript、ESLint、Vitest 全部通过。
