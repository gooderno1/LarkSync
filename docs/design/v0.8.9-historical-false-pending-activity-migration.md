# LarkSync v0.8.9 历史虚假待删活动迁移

## 1. 原因

`v0.8.8` 已在新下载扫描中先用完整云端 token 集合确认对象存在，因此不会再产生“记录待删后同轮取消”的新活动。旧版本已经写入的运行摘要仍带有 `delete_pending_files > 0`，会继续出现在活动列表。

正式库只读复核发现：

- 仅有待删计数、没有上传/下载/删除/冲突/失败的成功定时下载运行共 `536` 条。
- 其中 `534` 条的每个待删事件都能匹配 cloud 来源、状态 cancelled、原因为“云端文件已恢复”的墓碑。
- 通用匹配查询耗时约 `276.1ms`。

## 2. schema v5 规则

只有同时满足以下条件的历史运行改为 `legacy_check / has_activity=0`：

- 状态 success、无 last_error、触发源 scheduled_download。
- 上传、下载、删除、冲突、删除失败和普通失败计数均为 0。
- `delete_pending_files > 0`，且运行确有 `delete_pending` 事件。
- 该运行的每个 `delete_pending` 事件都能按 task_id 与完整 local_path 匹配 cloud 墓碑。
- 匹配墓碑状态为 cancelled，原因严格等于“云端文件已恢复”。

真实待删、匹配不完整、路径不同、本地来源、失败或有其他活动事实的运行保持可见。迁移只修改运行分类，不删除运行、事件或墓碑。

## 3. 验收

- 正式库只读 dry-run 预计归档 `534` 条，保留 `2` 条无法证明为虚假的待删运行。
- 新旧用户均通过 schema version 执行一次；重复初始化不重复修改。
- 活动页默认隐藏归档运行；需要审计时原始运行与事件仍在数据库中。
