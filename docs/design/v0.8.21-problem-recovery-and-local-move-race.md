# v0.8.21 问题恢复与本地移动竞态修复

## 目标

- 让问题中心只保留当前仍需处理的问题，已由同方向成功同步证明恢复的任务级异常自动结案。
- 消除本地文件或目录移动时“旧路径仍被上传”的竞态。
- 保留完整活动证据，同时修正历史运行汇总造成的异常次数污染。
- 保证所有失败事件至少包含异常类型，避免空白诊断信息。

## 根因

### 任务级异常没有按方向恢复

任务根目录上的下载错误会分类为`object_kind=task_run`和`operation_family=download`。旧结案逻辑只识别`operation_family=task_run`，所以即使后续下载成功也不会结案；同时，旧查询排除了`has_activity=false`的成功运行，使“完整扫描但全部对象未变化”的有效恢复事实失效。

### 移动事件与上传快照竞态

文件移动事件只把目标路径加入队列，没有移除源路径；目录移动事件被直接忽略。调度器取得旧路径后，源文件若在真正读取前被移动，就会抛出`FileNotFoundError`。这是状态已经变化的旧路径，不是需要用户修复的内容错误。

### 历史汇总与空异常降低诊断质量

旧版曾把任务完成汇总关联到问题出现记录，导致一个真实错误显示为多次异常。另有少数异常没有消息参数，`str(exc)`为空，无法在活动和问题中心定位异常类型。

## 状态判定

| 问题事实 | 恢复证据 | 结果 |
| --- | --- | --- |
| 任务级上传失败 | 同任务、后发生的上传成功运行 | 自动结案 |
| 任务级下载失败 | 同任务、后发生的下载成功运行 | 自动结案 |
| 任务级下载失败 | 仅有后发生的上传成功运行 | 保持未解决 |
| 全量扫描成功、全部对象跳过 | 方向匹配且结束时间晚于问题 | 可作为恢复证据 |
| 本地 I/O 目标仍存在 | 无其他恢复事实 | 保持未解决 |
| 本地 I/O 旧路径已不存在且任务根可访问 | 当前路径状态验证 | 自动结案 |
| 上传时源路径消失 | 再次检查确认不存在 | 记为跳过，不记失败 |

## 队列行为

文件移动时，监听器先删除源文件待上传项，再按目标路径排队。目录移动时，监听器删除源目录及其全部子项的待上传记录，并在线程中遍历目标目录，将实际存在且未命中忽略规则的文件重新排队。这样无论事件到达上传快照之前还是之后，都不会把旧路径长期保留为失败问题。

## 数据兼容

`problem_occurrence_recount_v1`只执行一次，处理`open`、`in_progress`、`waiting`和`ignored`问题。它从出现记录重新计数，排除严格匹配运行完成汇总格式的事件，不删除`sync_runs`、`sync_run_events`或`problem_occurrences`。因此活动审计完整，问题中心计数恢复真实口径。

## 验收边界

- 反方向成功运行不得结案任务级问题。
- 目标仍存在时的`FileNotFoundError`不得降级为跳过。
- 目录遍历必须在线程中执行，不能阻塞桌面 API 事件循环。
- 忽略目录、隐藏缓存路径和下载专用任务保持原有行为。
- 云端跨设备移动不在本次范围内，继续使用现有扫描和映射逻辑。
