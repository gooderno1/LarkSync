# v1.1.1 网络、转换与本地读写异常恢复

- 开发原因：转换失败使用 `operation_family=conversion`，成功事件仅提供 `upload`、`download` 或 `delete`，导致文件已恢复而告警持续等待。
- 同类问题：本地文件占用、路径或磁盘读写异常使用 `diagnostic`，同样无法匹配后续同步成功。
- 新事件：保留原分类、标题和严重程度；`network_remote`、`conversion`、`local_io` 从来源运行的 `trigger_source` 获取明确上传或下载方向，写入 `operation_family` 和 `resolution_key`。
- 旧分类迁移：传递来源运行方向，避免重新分类时丢失已经获取的方向。
- 历史记录：每轮最多修复 500 条 `open`、`in_progress`、`waiting`、`ignored` 记录；范围限于上述三类、旧方向为 `diagnostic`、`conversion` 或空值。
- 来源校验：必须存在对应失败事件及运行，且事件、运行和问题的账号、任务一致；方向不明确的记录不进入该批次，避免阻塞后续可修复记录。
- 恢复条件：账号、任务、规范化文件路径和方向一致，成功时间严格晚于最后失败时间；沿用已有成功事件及三方内容核验事实。
- 排除条件：反方向成功、其他账号／任务／文件、早于或等于失败时间的成功、手动双向运行等方向不明的失败均不能结案；普通“跳过”事件也不作为文件恢复证据。
- 历史证据：直接查询已消费的恢复事实，不回退实时游标，不重新同步文件，不清空活动日志。
- 审计：保持问题 ID、分类、指纹、出现次数及重试历史；结案保存成功事件、运行和时间；后续新失败重新打开问题。
- 版本兼容：复用现有数据字段、分类器 v3 和 schema v14，无数据库结构变更。
- 验证样例：10 秒上传过程中导入失败，20 秒同文件上传成功，历史等待告警自动结案；20 秒下载成功保持未解决。本地文件占用使用相同方向约束。
- 检查范围：上传、下载、删除已有对应恢复事件；冲突按冲突源状态核验，授权及任务级异常由现有运行／检查状态收敛。本次修复三类方向缺失及迁移传参，不改变其他恢复规则。
