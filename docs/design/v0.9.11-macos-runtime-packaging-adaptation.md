# v0.9.11 macOS 运行与打包适配

## 目标

- 在最新版 Device Flow 与多账号界面上恢复可信的 macOS 安装验收。
- 保证 Cocoa API 只在主线程执行，避免菜单栏进程与窗口子进程产生不稳定行为。
- 区分“关闭窗口”和“退出应用”，完整退出后不遗留后端或开发服务。
- 让没有安装 Homebrew 工具的 Mac 也能生成可安装 DMG。

## 行为契约

- 点击红色关闭按钮：隐藏窗口，同步服务继续在菜单栏运行。
- 从 Dock 或菜单栏再次打开：恢复现有窗口并置前，不重复启动 WebView。
- 使用 `⌘Q` 或应用菜单退出：Cocoa 允许窗口子进程正常结束；菜单栏父进程监测到正常退出后，依次清理窗口控制文件、后端与开发服务。
- 使用菜单栏“退出 LarkSync”：先执行相同清理，再停止菜单栏图标。
- 窗口恢复与置前：通过 `PyObjCTools.AppHelper.callAfter` 调度 AppKit 调用，不从控制服务或监测线程直接操作 Cocoa。

## DMG 构建契约

- `LARKSYNC_DMG_TOOL=auto`：优先 `create-dmg`，缺失时使用系统 `hdiutil`。
- `LARKSYNC_DMG_TOOL=create-dmg`：命令缺失时明确失败。
- `LARKSYNC_DMG_TOOL=hdiutil`：创建压缩 UDZO 镜像，包含 `LarkSync.app` 和指向 `/Applications` 的符号链接。
- 未显式提供 `APP_VERSION` 时，使用 POSIX 工具从后端 `pyproject.toml` 读取版本，不依赖 macOS 默认不存在的 `python` 命令。

## 安装冒烟契约

- 原生 Cocoa/WKWebView 检查当前账号连接首屏：根节点可见、阶段为 `choose_method`、第 1 次扫码操作可见且可用。
- 两次扫码与二维码渲染由独立 Playwright WebKit 测试使用 mock API 验证，避免原生首屏冒烟依赖真实飞书网络会话。
- 无交互式 WindowServer 时，只有原生进程停留在 `webview_starting` 且 PID 仍存活，才允许采用 headless WebKit 结果；原生进程已退出必须失败。

## 验收

- macOS 定向 pytest 覆盖主线程调度、退出清理、DMG fallback、当前首屏选择器和原生 PID 门禁。
- 前端 TypeScript、ESLint、Vitest 与生产构建通过。
- 后端全量 pytest 通过。
- 本机生成 arm64 `.app` 与 DMG，完成 Bundle、签名、挂载、安装复制、Keychain、后端健康检查和原生 WKWebView smoke。
