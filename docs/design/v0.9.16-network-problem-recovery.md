# v0.9.16 网络异常恢复结案

- 开发原因：定时上传的 `ReadTimeout('')` 被分类为 `network_remote`，其恢复方向却为 `diagnostic`；后续同文件 `uploaded` 事实无法匹配，重试后仍显示未解决。
- 新记录：保留网络异常分类、标题与严重程度；从失败事件所属运行的 `trigger_source` 获取明确的上传或下载方向，并用于 `operation_family` 和 `resolution_key`。
- 历史记录：每轮最多修复 500 条仍为 `diagnostic` 或空方向的活动网络问题；只处理来源事件、运行、任务和账号一致且方向明确的记录。
- 历史恢复：修正方向后直接查询已有恢复事实，不回退实时事件游标，不重放整个活动库。
- 结案条件：账号、任务、规范化文件路径和操作方向一致，且成功时间严格晚于最后失败时间。
- 排除条件：手动双向运行等方向不明确的失败、其他账号或文件的成功、反方向成功，以及发生在失败之前或同一时刻的成功，都不能作为结案证据。
- 审计：保留问题 ID、分类、出现次数、原始失败事件及重试记录；结案保存成功事件、运行和时间，清除旧忽略状态；重复执行幂等。
- 验证样例：10 秒上传超时、20 秒同文件上传成功，历史等待问题升级后结案；20 秒下载成功、其他文件上传成功或 9 秒上传成功仍保持未解决。
- 发布：v0.9.16；完成后端回归、前端质量门、隔离开发联调、Windows 安装启动和正式多平台构建验证。
