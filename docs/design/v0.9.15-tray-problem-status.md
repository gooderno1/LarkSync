# v0.9.15 托盘与统一问题状态

- 原因：问题中心按路径排除结案后，托盘仍统计 `conflicts.resolved=false`，导致页面为 0、托盘提示需要处理。
- 数据职责：`problems` 管理当前问题状态；`conflicts` 保留版本、哈希、预览和实际覆盖结果。此次不迁移或修改历史冲突数据。
- 统计范围：沿用请求账号上下文；托盘未指定账号时使用当前活动账号，与问题中心一致。
- 统计口径：复用 `ProblemService.get_summary()`；仅 `open,in_progress,waiting` 计入待处理。`resolved,ignored` 不计入。
- 接口：`/system/desktop/status` 增加 `problems.unresolved`；`conflicts.unresolved` 改为同一摘要中的未解决冲突分类数。`/tray/status` 增加 `unresolved_problems`，保留 `unresolved_conflicts` 并统一其口径。
- 托盘：当前待处理数大于 0 时显示需要处理；为 0 时按正在运行任务显示同步中或空闲。`last_error` 保留为运行诊断字段，不参与待处理判断。
- 异常：摘要读取失败时接口失败；托盘接口不可达或缺少新统计字段时保持异常提示，不把未知状态当成 0。状态查询不触发历史回填或修改问题生命周期。
- 通知：现有冲突提醒只使用问题摘要的未解决冲突数；其他类型通过托盘状态提示和问题中心处理。
- 验证样例：2 条原始未解决冲突对应的问题已按 `path_excluded` 结案时，问题中心、桌面状态和托盘均为 0，原始冲突及版本数据保留；另一个账号的未解决问题不混入当前账号。
- 验证范围：覆盖问题状态、账号隔离、历史错误、其他问题类型、查询失败、运行状态及通知；完成隔离开发联调、打包启动与正式 Release 检查。
