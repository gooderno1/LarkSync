# v0.9.12 macOS 钥匙串访问修复

## 原因与边界

- 删除应用包不会执行凭据清理；用户数据位于 `~/Library/Application Support/LarkSync`，凭据独立保存在登录钥匙串。
- v0.9.11 macOS 安装包使用 ad-hoc 签名，跨构建授权可能重新确认。当前 Windows 环境无法复现用户机器的实际 ACL 状态。
- Windows 为规避 CredWrite 长度限制而使用的 900 字符分片，也被用于 macOS；多个条目可能产生外观相同的授权弹窗。
- 已安装的 keyring macOS 后端通过删除再新增更新密码。新版改用 `SecItemUpdate` 保持条目身份。
- 后台轮询不能触发系统交互。授权被拒绝或系统读取失败后，应暂停系统调用并由用户主动重试。

## 实现契约

- Windows 继续使用现有分片存储；macOS 每账号使用一个完整 Token 包，仍由系统 Keychain 加密保存。
- macOS 原生适配器使用精确 service/account 查询；更新只修改 `kSecValueData`，不存在时才新增，禁止删除再新增。
- 非交互访问使用 `kSecUseAuthenticationUIFail`，需要授权时返回可识别状态；仅“重试钥匙串访问”允许系统交互。
- 文件型登录钥匙串可能忽略上述查询参数，因此同时在进程锁内使用 `SecKeychainGet/SetUserInteractionAllowed` 控制交互；每次调用（包括异常）恢复原状态，不改变系统策略。
- 一次读取失败后，后续后台请求复用暂停状态，不重复访问系统钥匙串。
- App Secret 成功读取（包括不存在）后缓存；显式重试重载缓存；保存和清除及时更新缓存。
- 新格式不存在时兼容旧分片/拆分/合并 Token；读取成功后复制为单条目。旧数据在新包写入成功前不清除；新格式存在但损坏时禁止回退旧凭据。
- 已迁移且账号命名空间凭据存在时，不再访问全局旧凭据或重复写回同一 Token。
- 页面明确区分“钥匙串访问受阻”和“飞书需要登录”；恢复过程不清空数据库、同步任务或已有凭据。
- 不修改 macOS 系统安全策略，不允许所有应用访问钥匙串，不将 Token 明文落盘。

## 验证

- 单测覆盖：长 Token 单条目、旧格式迁移、损坏拒绝回退、更新保留条目、拒绝后不重试、显式恢复、缓存失效、退出后不恢复旧凭据、Windows 原分片回归。
- 安装 smoke 使用应用实际存储类验证写入、重载、刷新和清除，覆盖 arm64/x86_64。
- 真机验收应覆盖：全新安装、只删除 `.app` 后重装、v0.9.11 覆盖升级、拒绝/始终允许、重启与 Token 刷新。
- 无交互式 Mac 验收前，不宣称已验证用户现场所有系统弹窗行为。
